# Re-audit — 12 September 2026

A companion to [`personal-expense-reconciliation-audit.md`](personal-expense-reconciliation-audit.md),
not a replacement for it. That report is kept exactly as written because it is the clearest
statement of what "phases 1–21 are complete" did and did not mean
([ADR-0050](../docs/decisions/0050-closing-the-audit-gaps-a-workflow-is-not-shipped-until-it-is-reachable.md)).
This document re-walks all 54 of its rows against the tree at the time of writing and says, for
each, what changed.

**Verdict: every row the original audit marked absent or partial now has a service, a registered
route and a browser surface, except where the absence is a decision.** Those exceptions are
named in full under "Still absent, deliberately" — there are four, and none of them is an
oversight.

Two limits on this verdict, stated first because they matter more than the table:

- **No live provider is connected, anywhere.** Splitwise, WhatsApp, the balance endpoint and the
  model provider are all configurable adapters that refuse **by name** when their credentials are
  absent. Everything below is verified against real code, a real database and a real browser —
  and against adapters pointed at scripted doubles. "Implemented" here never means "verified
  against a live account", and the difference is called out per row where it applies.
- **Seeded data is not evidence.** Rows are marked done on the strength of the service function,
  the registered route, the mounted screen and the tests, not on the presence of a synthetic
  scenario.

## Still absent, deliberately

Four things. Each is a decision with a written reason, not an unfinished row:

1. **Auto-approval from confidence** (row 43). `invariants.md` #16: confidence changes friction,
   never whether approval is required. "Learning" here can only mean proposing better.
2. **Natural-language entry** (row 45). ADR-0057 built the ask-only half. An instruction is
   refused by name and pointed at the screen that owns the act; staging one as a confirmable
   proposal needs an editor for stored proposals, which does not exist.
3. **A remote figure becoming a local one** (row 40). ADR-0056 reads Splitwise's side and records
   it; making their number true here is a person recording an `ExpenseAdjustment` with evidence
   (principle 9, `invariants.md` #6).
4. **Any live provider connection.** `CLAUDE.md` and `security-model.md` both forbid connecting a
   real bank, Splitwise or messaging account during development. Every adapter is configurable
   and refuses by name unconfigured.

## What "verified" meant here

- `npm run typecheck && npm run lint && npm run format:check && npm test` on the backend, against
  **both** database paths: PGlite in-process and a real PostgreSQL 16.15 via `TEST_DATABASE_URL`.
- `npm run typecheck && npm run lint && npm run format:check && npm test && npm run build` in
  `web/`.
- A driven browser against the real API process and a seeded synthetic database: both new
  workflows exercised end to end, including two writes (an adoption and a person mapping) whose
  audit events carry the actor and the reason. 14 screen states across desktop/mobile and
  light/dark reported **0 axe violations and no horizontal overflow**.
- The unconfigured states were checked as states, not as assumptions: the ask screen over a
  provider-less API, and a Splitwise discovery run whose read failed, which reported a failed
  check rather than agreement.
